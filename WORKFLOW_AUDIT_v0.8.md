## Fixes completed during this audit

1. **R35 document artifacts:** added `txt` and `zip` formats. The text download is the latest exact UTF-8 draft. ZIP includes every draft, used template-edition snapshots, a file/body-hash manifest and instructions. HTTP test reads the actual ZIP, verifies byte hashes, publishes a new edition, and confirms historical TXT and ZIP artifacts remain byte-identical.
2. **R38 recipient handoff:** HTTP test now uses a creator, preparer and a distinct receiving lawyer. The receiving lawyer sees the queue, accepts and approves; creator acceptance/approval attempts are rejected. Restricted fields remain absent from downloadable artifact.
3. **R38 changed reviewer invalidation:** acceptance must match the current assigned reviewer. Reassignment blocks submission and old acceptance exports until the new lawyer accepts; the HTTP test verifies the transition.
4. **R37 form usability:** added fixture JSON shape hint to the new-candidate action.

After these changes: `TMPDIR="$PWD/.work" node --test tests/practice-operations-workflows.test.mjs` passes **14/14**.

## Integration findings and resolution

- **R63 cross-path bypass fixed.** The initial audit found separate specialist/legacy holds. Root added current same-matter hold aggregation across both stores, authorization/export checks, native retention rejection, and a bounded HTTP cron proposal runner. The new R63 HTTP test exercises cross-assignment holds, blocked native disposition, native-to-workbench holds, and a hold appearing between scheduler reads. Hosted scheduling and external connector execution remain unverified.
- **R17 escalation recipient fixed:** now constrained to current assigned reviewer, whose queue already receives the work. **R60 retry recipient fixed:** constrained to the assigned reviewer; an authenticated negative test rejects a fictional recipient.
- **R17 intake bridge implemented and tested locally:** current signed evidence matches inquiry ID, request reference and assigned participants; intake receives only minimal status and matter opening checks current clearance. Actual external identity verification remains outside the evidence.
- **Internal versus outward artifacts:** R24/R31 internal review JSON may carry privileged history; recipient-safe production formats must remain clearly labeled. Current workbench UI calls JSON “Internal verification record,” which is appropriate.
